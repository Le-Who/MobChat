# Own chat state on the server and snapshot provider requests

Each world owns its chat map, session, and save file. Admit a request before consuming a reaction allowance or preparing side effects. Capture the player, mob, world, and state identities before dispatch. Timer and HTTP callbacks recheck ownership after the server executor handoff. An unfinished request cannot survive a reload. Stop producers before the shutdown snapshot. Serialize the complete snapshot before touching the save path, and preserve unreadable saves for recovery.

The automatic reaction bucket refills on the availability check. Reserve a token only after that check succeeds. The autosave timer can race with shutdown, so a rejection from an already closed scheduler is expected. NPC chat stays on the server so inventory loot generation and social effects happen once.

Moving a bucketed entity can change its UUID. The `CCUUID` bridge moves its saved chat record to the new identity. Relationship projection uses the viewer UUID, then the old display-name entry, then the legacy blank entry. A login packet leaves the saved map untouched so actual interactions can still migrate the display-name entry. Keep the entity update's map wire format with a single UUID entry so older clients can decode it. Compress login JSON as UTF-8 and split it into byte chunks. Fabric's payload codec must consume the complete receive buffer and leave the reusable send buffer position intact.

Both provider clients use one runner that snapshots the configuration, prompt, and history before asynchronous work. Fallback cursors belong to that request. Traverse other candidates before the final transient connection retry. Each HTTP attempt reserves quota, a successful retry clears earlier failure diagnostics, and a stale request cannot write newer administrator settings. A provider cooldown and the minute window survive the Pacific daily reset. A visible provider error stays outside the model's history, while a successful reply displays cleaned text and retains its structured original for context.

Redact provider bodies and headers before parsing or logging. Redact overlapping keys longest first. Decode JSON string tokens before matching so escapes cannot conceal part of a key, then reserialize only affected tokens to preserve fences, partial replies, and action text. Configuration parse exceptions can include stored key text, so report the path without dumping Gson's error input. A malformed world configuration uses uncredentialed defaults. `custom_roles.json` is created only when missing because an empty or unreadable file can be deliberate or recoverable.

The Gemini-compatible endpoint needs a user turn even for an empty history. Native Gemini rewrites explicit `generateContent` URLs to the selected fallback model, omits `temperature` for Flash-Lite, and strips `additionalProperties` from the native schema copy because native `responseSchema` uses a restricted OpenAPI subset. Keep token-limit diagnostics even when the candidate has no text. The explicit native entry point shares the runner with production dispatch so loopback tests exercise its retry policy.

The character normalizer produces the legacy sheet format used by UI and prompt context. World-clock text uses Minecraft's 6 AM origin. Live model behavior tests require an explicit key and append to a comparison file. Local HTTP tests use fixtures, including concurrently handled timeout and retry requests so a stalled first request does not block a later one.

An update stages a jar after checking the downloaded digest. Applying an existing stage revalidates the target, running version, and digest. A damaged or incompatible stage can be replaced by the latest compatible release. The standalone helper waits for JVM exit and keeps the original jar as a backup. It preserves a separate file that already occupies the stable install name.
